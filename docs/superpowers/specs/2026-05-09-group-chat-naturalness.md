# 群聊自然度优化设计文档

**日期：** 2026-05-09
**分支：** brave
**范围：** AgentInvoker 群聊上下文注入优化

---

## 背景与问题

当前群聊实现中，Agent 的回复存在两类违和感：

1. **历史污染**：Agent 会评论与本轮问题无关的历史对话内容（如尼波评论了前几轮哈尔的日志分析）
2. **越界回答**：当用户问"你们几个的 X 是什么"时，每个 Agent 都试图回答所有人的部分，而不是只回答自己的

根本原因：`agentInvoker.ts` 的群聊上下文注入（`groupContext`）只告知了 Agent 它在群聊中，但没有约束它的回答范围和历史使用方式。

---

## 设计

### 改动范围

仅修改 `src/main/presenter/agentChat/agentInvoker.ts` 的 `buildLLMMessages` 方法，两处改动：

1. **扩展群聊 system-reminder**：在现有群聊环境信息后追加三条行为规则
2. **历史消息加轮次标记**：在转换历史消息时给用户消息和 Agent 回复加 `[Round N]` 前缀

### 1. 扩展 groupContext

**改动前：**

```
你正在参与一个群聊。群聊中的其他参与者 ID 为：[...]。消息中以 [agentId]: 开头的内容来自其他参与者。当前用户名：xxx。
```

**改动后：**

```
你正在参与一个群聊。群聊中的其他参与者 ID 为：[...]。消息中以 [agentId]: 开头的内容来自其他参与者。当前用户名：xxx。

群聊行为规则：
1. 本轮用户消息是历史中最后一条 [用户] 消息，你只需要回答这条消息，不要主动评论或引用之前轮次的内容，除非用户明确提到了历史内容。
2. 如果用户问题涉及多个参与者（例如"你们几个的 X 是什么"），你只回答属于你自己的部分，不猜测、不评论其他参与者。
3. 历史消息仅供理解对话背景，不是你需要逐一回应的内容。
```

### 2. 历史消息轮次标记

在 `buildLLMMessages` 的历史消息转换循环中，遍历 `groupMessages` 时维护一个 `roundIndex` 计数器：

- 每遇到一条 `senderAgentId === null`（用户消息），`roundIndex++`
- 用户消息格式：`[Round N] <原始内容>`
- Agent 消息格式：`[Round N] <原始内容>`（使用遇到该消息时的当前 roundIndex）

示例输出：

```
[Round 1] 用户: 帮我看看今天的日志
[Round 1] [hal-ai]: ...（日志分析内容）
[Round 2] 用户: @哈尔 @莫斯 @尼波 你们仨的 mbti 是啥
```

## 实现

### 修改文件

`src/main/presenter/agentChat/agentInvoker.ts`

**改动一：groupContext 字符串（约第 100 行）**

```typescript
const groupContext = `你正在参与一个群聊。${otherParticipants}消息中以 [agentId]: 开头的内容来自其他参与者。${userInfo}

群聊行为规则：
1. 本轮用户消息是历史中最后一条 [用户] 消息，你只需要回答这条消息，不要主动评论或引用之前轮次的内容，除非用户明确提到了历史内容。
2. 如果用户问题涉及多个参与者（例如"你们几个的 X 是什么"），你只回答属于你自己的部分，不猜测、不评论其他参与者。
3. 历史消息仅供理解对话背景，不是你需要逐一回应的内容。`;
```

**改动二：历史消息转换循环（约第 111-143 行）**

在循环前初始化 `let roundIndex = 0`，每条用户消息前 `roundIndex++`，所有消息内容前加 `[Round ${roundIndex}] `。

## 权衡

- **约束是软性的**：LLM 可能偶尔不遵守，特别是强性格 Agent（如哈尔 INTJ）。可通过后续观察决定是否进一步加强措辞。
- **轮次标记增加 token**：每条历史消息多约 10 个 token，可接受。
- **不改数据层**：无需迁移，改动完全向后兼容。
